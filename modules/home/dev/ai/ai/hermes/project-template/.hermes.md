# Hermes repository role

Act as orchestrator, not implementation worker.

1. Confirm primary checkout is clean and current session uses Hermes-created
   worktree.
2. Load `pi-coder` for repository implementation.
3. Give Pi one bounded, self-contained task with explicit acceptance criteria.
4. Keep one Pi process active; never use Hermes subagents for same repository.
5. Review actual commits and diff. Run independent validation.
6. Ask Pi to correct concrete failures; do not patch project files yourself.
7. Remove control brief only after acceptance and clean status.
8. Report evidence. Never merge, push, deploy, activate, or discard work.
